# 哪些内容可以开源，哪些必须留在本机

适用范围：MakeUp 的 Git 文件、历史提交、Issue、PR、构建产物、测试附件和日志。日期：2026-09-09。

## 必须排除的数据

| 类别 | 这个项目中的例子 | 为什么不能默认公开 |
|---|---|---|
| 凭据 | Firebase Admin 私钥、服务账号 JSON、模型 API key、GitHub token、签名私钥和证书 | 可能授予账户、数据库、算力或发布权限 |
| 真人生物特征 | 照片、视频、关键点、原始深度、姿态、纹理、`.makeupscan`、`.makeupcapture`、GLB | 可以识别人，甚至包含比原图更丰富的面部信息 |
| 账号与业务记录 | `.firebase/` 模拟器导出、用户资料、UID、配方关联、会话 token、日志 | 本地测试数据也可能来自真实用户 |
| 设备与个人配置 | `.env*`、真实 Firebase 配置、`project.local.yml`、本机绝对路径、个人邮箱、设备标识 | 与开源代码无关，可能暴露账户或设备信息 |
| 私人工作记录 | 内部 HANDOVER、聊天衍生笔记、私人 QA 截图、测试收据与预算记录 | 不属于公共接口或通用技术说明 |
| 未获分发许可的资产 | 研究模型权重、真实人像数据集、品牌宣传图片 | “网上可下载”不代表允许再分发或用于产品 |

改名、裁剪文件名、删除 EXIF 或只导出网格，都不能自动让个人脸部数据变成匿名数据。需要公开演示时，先取得适用于该用途的授权，或使用不包含真人信息的合成素材；本次发布不附带真人测试样本。

## 可以保留的内容

- 自己编写的客户端、着色器、采集与文件处理逻辑、测试程序。
- 空的 `.env.example`、Apple `project.local.example.yml`、`demo-makeup` 配置及模拟器专用 `demo-api-key`。
- 不含账号数据的 Firestore 规则、索引、类型定义和示例产品参数。
- 有上游来源和许可证的 MediaPipe 规范脸拓扑。它是公共通用模型，不是个人扫描。
- 依赖清单、锁文件、许可证、通用架构与操作说明。

Firebase Web 的 API key 与 Admin 私钥不是一回事：前者主要用于识别项目，数据访问依赖规则和权限。不过本仓库仍只提供空模板，避免把个人项目配置作为默认值分发；付费模型 API key 绝不能放进 `VITE_*`。参见 [Firebase 官方说明](https://firebase.google.com/docs/projects/api-keys)。

Apple Team ID 和 Bundle ID 也不是签名私钥，但不需要把维护者个人配置硬编码给所有贡献者。公开工程使用示例标识，实际签名写入被忽略的本地覆盖文件。

## 三层检查

1. **忽略规则**：`.gitignore` 排除密钥、本机配置、真人素材、扫描导出、权重、模拟器数据和内部记录。它不会自动取消跟踪已经入库的文件。
2. **公开文件审计**：`python3 scripts/security/audit_public.py --staged` 读取真实 Git 索引，拒绝敏感路径、未审查二进制和常见敏感文本；`--history` 检查当前仓库所有可达文件对象。报告只打印文件位置和问题类型，不输出密钥值。
3. **专用密钥扫描**：CI 用固定版本且校验 SHA-256 的 Gitleaks 扫描 Git 文件历史。维护者同时审查提交作者信息、文档、附件和服务配置。

这些检查是工程防线，不能证明“绝对没有秘密”。不应通过修改忽略清单、改后缀或 `git add -f` 来绕开检查。

## 发布与历史

本次公开代码从独立发布副本整理，开发机的历史提交与私人文件不随源码推送。保留远端原有的 MIT 许可证及其初始化历史；新提交使用 GitHub noreply 地址。仓库所有者之前已经公开的提交作者信息，不会因本次文件审计而自动消失。

发现历史中有真实凭据时，应先吊销，再清理相关分支、标签和历史，并检查发布附件与缓存。历史改写可能影响协作者，需要单独协调，不能认为一次删除文件就完成处理。

## 贡献者操作

```sh
# 查看将要公开的文件与改动
git diff --cached --stat
git diff --cached
python3 scripts/security/audit_public.py --staged

# 在不含私人开发历史的公开 checkout 中检查历史
python3 scripts/security/audit_public.py --history
```

截图、Issue 和 PR 正文也必须遵守相同规则。图片夹具放到 README 指定的本地忽略目录；不要作为 GitHub Actions 附件上传。
