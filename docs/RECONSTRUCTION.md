# 重建现状与研究方向

更新：2026-09-09。这里描述可复查的能力边界，不将研究论文的效果或速度当成本项目已经做到的结果。

## 已经实现

- Web 连续录像、姿态/清晰度候选、原视频保存与导出。
- 基于 MediaPipe 的粗略脸部几何、纹理融合、Three.js 查看及 GLB 导出。
- Apple ARKit 面部网格与原始 TrueDepth 可见表面实验流程。
- 在现有脸部表面上编辑近似妆容、比较原图和渲染结果。

这些流程没有完成高保真的个人整头还原。头发在原图里可见，不代表已有相应 3D 几何；纹理接缝改善也不会新增耳朵结构。

## 需要分别验收的目标

1. **身份相似度**：正面、侧面和轮廓是否像同一个人。
2. **观测覆盖**：哪些部位真正被输入拍到，哪些来自模板或推断。
3. **资产可用性**：输出是否为可加载的网格或 Gaussian 资产，而不只是一段渲染视频。
4. **编辑能力**：能否在正确表面修改肤色、粗糙度、法线和妆容。
5. **总时延和费用**：上传、排队、预处理、推理、导出与浏览器呈现均要计时；故障与重复请求同样计费。

## 有限范围的候选研究

| 路线 | 可研究的问题 | 当前缺口 |
|---|---|---|
| [LAM](https://github.com/aigc3d/LAM) | 少量输入的 Gaussian 头像外观 | 官方实现依赖 CUDA；公开演示不等于可导出的完整资产；权重与依赖许可需逐项核实 |
| [FastAvatar](https://github.com/TyrionWuYue/FastAvatar) | 多帧/视频输入的头像 | 需预处理、CUDA 环境、资产导出及浏览器适配；不能只统计网络 forward 时间 |
| [ELITE](https://github.com/kaist-ami/ELITE) | 稀疏帧外观与个人化 | 个人优化时间及输入要求需要实测，不作为已验证的即时服务 |
| [GTAvatar](https://github.com/KelianB/GTAvatar) | 材质分解、编辑与重打光 | 长时优化不适合直接承诺几分钟内完成 |
| [KeenTools](https://cloud.keentools.io/docs/reference) | 多图脸型、网格和 UV 基线 | 不还原本人真实发型，不能单独完成整头目标 |

2026-09-08 的 LAM 官方托管演示在使用其内置样例时返回上游异常，没有得到模型。这个失败不能用于评价模型正常情况下的质量或成功耗时。KeenTools 客户端只有离线协议/预算测试，没有本项目真实账户的成功重建结果。

`scripts/model-eval/` 提供只读预检、默认 dry-run 的演示探针和显式执行的公共样例基准。不会随源码分发人像、研究权重或用户账单。详见 [评估工具](../scripts/model-eval/README.md)。

## 许可证与部署边界

主代码开源不表示权重、FLAME 依赖或数据集也按同一许可分发。研究所需资产应从上游获取并逐项确认用途；本仓库不附带这些资产，也不保证它们适用于商业服务。

缺少观测的后脑或另一侧可以被模型估计，但不能称作对本人真实结构的测量。尚未实际验证的方案，不进入默认用户流程并宣称完成。
