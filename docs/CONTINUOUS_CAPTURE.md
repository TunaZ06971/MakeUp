# 新版网页连续采集：操作与数据说明

更新：2026-09-09。入口是 [本地采集页](http://127.0.0.1:5173/capture)。这个版本先解决采集体验和素材保存；**尚未接通高精度完整头部重建**，不会把旧的 468 点脸部网格当成新模型返回。

## 你现在怎么用

1. 在运行开发服务器的电脑上用 Chrome 打开上面的链接，刷新一次。页首会显示当前源码版本。无需登录，也无需先启动 Firebase。
2. 保持自然表情、均匀光线，让头顶和头发两侧都留在画面里。选一个方便转头的方向，点击“开始录像”，允许摄像头权限。
3. 正对镜头稍停，慢慢转向舒服的一侧，再回到正面。**不要求达到 90°，不需要刻意眨眼或张嘴，也没有必须命中的姿态检查点。** 摄像头预览是镜像，保存视频保持相机原始方向。
4. 随时点击“结束并保存”；到约 25 秒会自动停止。侧面检测不到人脸时，视频仍然继续录制。系统只从检测成功、较清晰且表情自然的画面中挑候选帧。
5. 回看视频：头发轮廓有没有出画？侧面有没有拍到？需要补充时只补录一段，原片段保留。一个采集包最多 4 段，总媒体大小最多 90 MB。
6. 点击“导出采集包”，得到 `MakeUp-head.makeupcapture`。把文件留在本机，仅在明确授权的本机测试中使用同一份输入比较模型，不要上传到公共 Issue。

本地采集不需要 NVIDIA 显卡，也不需要部署服务器。手机浏览器不应直接打开 Mac 的 `127.0.0.1`；自动化主要验证本机网页，iPhone 原生 TrueDepth 仍是另一条实验流程。

## 界面的勾选代表什么

“正面、向左转、进一步向左”等只表示检测到相应**脸部姿态的候选帧**。它们不是耳朵、头发、后脑已完整测量的证明，也不是 3D 模型精度分数。

- 姿态失败、模糊、遮挡或眨眼只影响当前帧能否成为候选，不会把已经采到的角度清零。
- 每段每个姿态最多保留 2 个间隔至少约 0.7 秒的候选帧，质量较高的画面可替换较差画面。
- 检测器加载失败或超时，会显示提示，视频仍可保存；下游模型还可以重新分析原视频。
- 用户只拍一侧时，另一侧和后脑缺少观测。这些区域如果由模型补全，必须标成估计，不能算实测还原。

## 保存与隐私

新入口使用浏览器 IndexedDB 的 `makeup-head-captures` 数据库，和账号、旧 `.makeupscan` 模型相互独立。不录声音、不自动上传，也不写入 Firebase。

- “保存在此设备”更准确地说是保存在**当前浏览器、当前网址的站点空间**；`localhost` 和 `127.0.0.1` 不共用站点数据。换浏览器或清除站点数据后，需重新导入导出的包。
- 切到后台会停止录制，并尝试保存已经录到的片段。停止、取消和晚到的摄像头授权都会关闭所有摄像头轨道。
- 正在录制、保存或保存失败但录像仍在内存时，页面会请求浏览器阻止直接离开。**录像期间强制退出浏览器、系统终止进程或直接断电仍可能丢失未保存内容**；当前没有持续落盘的分块草稿。
- 本地存储失败时可以下载原视频，也可以重试本地保存。请先保存原视频再关闭页面。
- 导入不会覆盖已有采集，包括另一标签页后来写入的采集。需要更换时，先导出，再主动清空当前采集。

## 文件格式

`.makeupcapture` 是 ZIP 容器，和旧 `.makeupscan` 的 JSON 模型格式不同。当前仅新版 Web 支持该容器；**不能直接拿到 Apple 客户端或旧模型导入按钮中打开**。

```text
MakeUp-head.makeupcapture
├── manifest.json
├── segments/
│   └── <片段 ID>.webm 或 .mp4
└── frames/
    └── <候选帧 ID>.jpg
```

清单中保存：协议 `continuous-rgb-v1`、采集时间、期望转头方向、片段时长/分辨率、候选帧时间/姿态/评分/关键点，以及片段终止原因。`reconstruction` 固定为 `not-run`。关键点只用于选帧和未来对齐，不是输出模型的几何。

完整视频由浏览器 MediaRecorder 保存；JPEG 候选帧宽度最多 1920 像素。ZIP 打包不再次损失性转码。实际视频分辨率和格式由摄像头、浏览器能力决定；申请 1080p 不代表设备一定提供 1080p。

导入限制包括文件大小、解压体积、条目数量、路径白名单、重复条目、声明尺寸与实际尺寸、片段/关键点字段和媒体类型。它验证容器和结构；不代表对每一个媒体字节完成专业解码或质量验收。

| 浏览器与归档验证 | `web/tests/head-capture.spec.ts` | Playwright、真实 MediaRecorder、真实 MediaPipe Worker |

## 与重建评估衔接

模型适配器应该消费本包中的原始视频或筛选帧，返回能验证来源和格式的真实 3D 资产。五分钟目标必须计入上传、排队、预处理、推理和下载。目标和当前缺口见 [重建研究方向](RECONSTRUCTION.md)。

当前没有“生成精细模型”的可用网页按钮。头发、耳朵、本人脸型和可编辑妆容的质量仍需逐项验收；这些不能由录像保存成功或测试通过推导出来。
